# 备份、导出与恢复演练

VibeBus 的在线备份是一致的 SQLite 恢复点。一份可用的导出由三个保持在一起的组成部分构成：

1. 项目标记 `.vibebus/project.json`；
2. 由 `vibebus backup` 生成的数据库；
3. 外部恢复清单（inventory）中返回的 SHA-256 摘要和字节数。

数据库中包含的是智能体和操作员的凭据摘要，而非存储在 Windows 凭据管理器或 macOS 钥匙串（Keychain）中的密钥。因此，迁移到另一个用户或主机时，还需要单独保留的智能体恢复密钥（recovery key），或做出另一项明确的身份恢复决策。切勿将持有者令牌、恢复密钥、操作员密钥、保险库导出、签名凭据或云凭据加入恢复包。

对于 G1 Windows 发布候选版，请将恢复证据与发布证据分开保管：在恢复流程下保留项目标记/数据库清单，在发布记录中保留已签名的 Windows 产物、`SHA256SUMS.txt`、`release-manifest.json`、CycloneDX SBOM 和 `supply-chain-evidence.json`。两组证据不可互相替代。

## 自动化一次性演练

构建发布二进制后，运行仓库自带的演练脚本：

```powershell
./scripts/test-backup-restore.ps1 -BinaryPath ./target/release/vibebus.exe
```

该脚本仅使用系统临时目录下的一个随机目录。它会创建一个智能体和一个任务，执行一次在线备份，在该恢复点之后创建第二个任务，然后将标记与备份导入到一个独立的根目录和数据主目录（data home）中。验收要求：

- 导入的文件哈希与备份的 SHA-256 一致；
- `doctor.ok=true`、schema 13、WAL 及外键均启用；
- 恢复后的智能体凭据摘要能够接受原始进程内令牌；
- 恢复后的项目中仅存在备份前的任务；
- 备份后创建的任务仍然不存在；
- 临时源、导出和恢复的数据均被删除；
- 不打印任何凭据或恢复密钥。

该演练绝不会读取、替换、压缩或修改正在运行的项目数据库。

## 生产环境恢复流程

VibeBus 刻意不将破坏性切换自动化。对于真实恢复：

1. 停止所有使用目标项目的 CLI、MCP、Hook 和 Codex 任务。在 VibeBus 之外记录维护窗口，因为权威数据库即将离线。
2. 尽可能为当前数据库创建最后一次在线备份并保留其哈希。不要覆盖更早的恢复点。
3. 将目标项目的 `.vibebus/project.json` 复制到隔离的恢复根目录。确认其 `projectId` 是预期的项目。
4. 将所选备份在不作编辑的情况下复制到 `<isolated-data-home>/projects/<projectId>/vibebus.db`。
5. 针对隔离根目录和隔离数据主目录运行 `doctor`、`status` 及带认证的只读检查。将任务、智能体、制品、绑定、路径预留、事件和留存的预期与恢复清单进行比对。
6. 如果操作系统保险库条目不可用，请通过文档化的恢复流程使用单独保管的智能体恢复密钥。不要把数据库摘要当作可恢复的密钥。
7. 只有在隔离验证通过之后，才做出由维护者控制的、单独的离线切换决策。保留被替换的数据库作为回滚制品，并在向所有任务重新开放项目之前，先重启一个客户端。

不要只把 `vibebus.db` 复制到不相关的项目标记中。不要在任一 VibeBus 进程运行期间替换数据库。不要通过重放原始 SQL 或编辑项目 ID 的方式恢复。

## 物理压缩边界

逻辑留存仍与 SQLite 文件压缩相互独立，且恢复演练从不运行 `VACUUM`。物理压缩现在只能在真实终端中通过 `vibebus maintenance compact --root <project> --backup <new-path>` 执行。它要求输入完全匹配的 `compact:<project-id>` 确认、当前由保险库支持的操作员密钥、项目完全停机、零活动任务/绑定/路径预留、快速失败（fail-fast）的独占 SQLite 边界、所在卷上至少有数据库两倍大小的可用空间，以及一个新的备份路径。VibeBus 会在 `VACUUM` 之前创建并校验该备份，然后恢复/检查点 WAL，并返回有界的压缩前后哈希、大小、页数、回收字节数与完整性证据。该命令在 MCP 中不可用。务必先在一次性的恢复副本上测试该命令；仓库测试只在临时项目/数据主目录下调用压缩，本轮实现并未对正在运行的 VibeBus 项目执行过该操作。
